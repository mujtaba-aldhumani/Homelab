## Work Completed

### Active Directory — Domain Controller Build and First GPO

Goal: stand up a working Active Directory domain from scratch — domain controller, OU structure, security groups, a real Group Policy, and a domain-joined client to prove enforcement — as the next homelab portfolio project.

* Confirmed Windows 11 (VM100) cannot run AD DS at all and built a new dedicated Windows Server 2022 VM (DC01, VMID 103) instead — see [Windows Server VM over Windows 11 VM for Active Directory](../Decisions/Windows%20Server%20VM%20over%20Windows%2011%20VM%20for%20Active%20Directory.md)
* Set DC01 static IP 192.168.86.203, renamed to DC01, promoted to the first domain controller of a new forest — chose `mujtaba.internal` as the domain name over `.local` or a public-domain subdomain — see [Reserved .internal TLD over .local for AD Domain Name](../Decisions/Reserved%20.internal%20TLD%20over%20.local%20for%20AD%20Domain%20Name.md)
* Repointed DC01's own DNS to itself (127.0.0.1) post-promotion; set an external NTP source and corrected the timezone, since DC01 is the forest's PDC emulator with nothing above it in the time hierarchy by default
* Ran `dcdiag` after the NTP fix — all tests passing clean
* Built OU structure: top-level `_Admin`, `Groups`, and `Service Accounts`, plus a `Departments` parent OU containing `Sales`/`IT`/`HR` sub-OUs
* Created a personal admin account (in `_Admin`, added to Domain Admins) separate from the built-in Administrator account, and one fictional user per department (Sam Patel/HR, Alex Chen/IT, Jordan Lee/Sales), each with Department/Job Title attributes filled in
* Created matching security groups (IT-Staff, Sales-Staff, HR-Staff) in the `Groups` OU, one member each — kept separate from the OU structure since OUs and groups serve different purposes (organization/policy vs. access control)
* Built GPO "IT - Restrict Control Panel" (Prohibit access to Control Panel and PC settings) and linked it once at the `Departments` parent OU so it inherits down to all three sub-OUs, rather than linking it three separate times
* Domain-joined VM100 (Windows 11) to `mujtaba.internal`, pointing its DNS at DC01 first
* Logged into VM100 live as alex.chen and confirmed Control Panel access is actually blocked — full chain (OU → group → GPO → inheritance → client enforcement) working end-to-end
