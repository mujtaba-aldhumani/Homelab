## Work Completed

### Zammad — Platform Choice and Container Build

Started the next candidate project from the rotation: a helpdesk/ticketing system, following the [Active Directory](../Projects/Active%20Directory.md) project's completion.

* Weighed osTicket vs Zammad and chose Zammad for its multi-service architecture and closer resemblance to a modern support org — [Zammad over osTicket for Ticketing Project](../Decisions/Zammad%20over%20osTicket%20for%20Ticketing%20Project.md)
* Decided to deploy as a Privileged LXC over the script's Unprivileged default, given Elasticsearch's documented reliability issues in unprivileged containers — [Privileged over Unprivileged LXC for Zammad](../Decisions/Privileged%20over%20Unprivileged%20LXC%20for%20Zammad.md)
* Built the container (VMID 104, static IP `192.168.86.204/24`) via Proxmox Community Scripts in Advanced Settings mode

#### Troubleshooting

* First attempt to run the install script produced no output at all — [Community Script Produces No Output on First Run](../Troubleshooting/Community%20Script%20Produces%20No%20Output%20on%20First%20Run.md)
* The setup wizard defaulted Container Type to Unprivileged with no way to navigate back and correct it — [LXC Setup Wizard Cannot Revisit Container Type Field](../Troubleshooting/LXC%20Setup%20Wizard%20Cannot%20Revisit%20Container%20Type%20Field.md)
* A host-level package upgrade prompted mid-script hit an expected, benign enterprise-repo auth error — [Proxmox Host Upgrade Fails on Enterprise Repository Without Subscription](../Troubleshooting/Proxmox%20Host%20Upgrade%20Fails%20on%20Enterprise%20Repository%20Without%20Subscription.md)
* The first build reported success but the site was unreachable and console login failed — diagnosis found the in-container application install had never actually run — [Interrupted Zammad Install Leaves Container Running With No Services](../Troubleshooting/Interrupted%20Zammad%20Install%20Leaves%20Container%20Running%20With%20No%20Services.md)
* Destroyed and rebuilt the container from scratch, staying in one uninterrupted session and correctly selecting Privileged — install succeeded
* Post-rebuild, all Zammad systemd units showed `sleep infinity` as their Main PID, which looked broken but was confirmed as normal packaging behavior — [Zammad systemd Units Show sleep infinity as Main Process](../Troubleshooting/Zammad%20systemd%20Units%20Show%20sleep%20infinity%20as%20Main%20Process.md)

### Result

* Zammad container rebuilt as Privileged and confirmed healthy: Elasticsearch stable, and real Puma/nginx/websocket processes verified listening and serving traffic
* Reached the Zammad login page successfully
