## Work Completed

### Active Directory — Bulk Provisioning, File Server, and Software Deployment

Continuation of the AD project, extending the core build (domain controller, OUs/groups, Control Panel GPO) from [2026-08-27](2026-08-27.md) with three further pieces before moving to the next homelab project.

**Bulk user provisioning and account lifecycle**

* Wrote a PowerShell script (`New-ADUser` in a loop over `Import-Csv`) provisioning 51 fake employees from a CSV, 17 per department, mapping the `Department` column directly to the matching OU path
* Script is idempotent (checks `Get-ADUser` before creating) and forces a password change at first logon, matching the manually-created accounts' setup
* Ran cleanly on the first pass — all 51 created, verified via `Get-ADUser -Filter * -SearchBase` returning a count of 54 (3 original + 51 new)
* Practiced disable, password reset, unlock, and OU-move via ADUC rather than PowerShell — see [GUI over PowerShell for Account-Lifecycle Practice](../Decisions/GUI%20over%20PowerShell%20for%20Account-Lifecycle%20Practice.md)

**File server and NTFS permissions**

* Built `C:\CompanyShare` with `IT`/`Sales`/`HR`/`Public` subfolders, finally putting the `IT-Staff`/`Sales-Staff`/`HR-Staff` security groups to use
* Set share permissions loosely and did all real access control at the NTFS layer — see [NTFS Permissions over Share Permissions for Access Control](../Decisions/NTFS%20Permissions%20over%20Share%20Permissions%20for%20Access%20Control.md)
* Verified least-privilege access by logging in as `alex.chen` (IT) and `jordan.lee` (Sales) — each could access only their own department's folder, both could read but not write to `Public`

**GPO software deployment**

* Discovered VM100's computer object was sitting in the default `Computers` container, unreachable by any OU-linked GPO — created a dedicated `Workstations` OU and moved it there — see [Dedicated Workstations OU for Software Deployment GPO Scope](../Decisions/Dedicated%20Workstations%20OU%20for%20Software%20Deployment%20GPO%20Scope.md)
* Shared an MSI (7-Zip) over the network and created a GPO assigning it via Computer Configuration > Software Installation
* Hit the package-selection dialog defaulting to a local-drive view instead of the network share — [GPO Software Package Browser Defaults to Local Drive](../Troubleshooting/GPO%20Software%20Package%20Browser%20Defaults%20to%20Local%20Drive.md)
* Rebooted VM100 and confirmed 7-Zip installed automatically and silently, with zero user interaction
