8.8.4.4 Secondary DNS over Blank Fallback for Pi-hole

## Decision

Kept the existing public secondary DNS server (`8.8.4.4`) as a fallback when switching the network's primary DNS to Pi-hole, rather than leaving secondary DNS blank.

## Context

Google Wifi's DNS was already custom-configured (primary `8.8.8.8`, secondary `8.8.4.4`) prior to this project. When pointing the network's primary DNS at Pi-hole (`192.168.86.202`) to enable network-wide ad blocking, a decision was needed on what to do with the secondary DNS slot.

## Reasoning

Leaving secondary blank means the entire home network loses DNS resolution — effectively losing internet access — the moment Pi-hole goes down, which is a harsh failure mode for a container that's still fairly new. Keeping `8.8.4.4` as secondary means DNS keeps working through any Pi-hole outage, at the cost of ad-blocking and query logging silently going dark during that window with no obvious signal. Since the network had already been running fine on that address and the immediate priority was getting ad blocking live and stable rather than being airtight about outage visibility, resilience was chosen over strictness for now.

## Alternatives Considered

- Leaving secondary blank — rejected as too risky for a still-new, not-yet-proven container. Forces the whole house offline on any Pi-hole hiccup.

## Status

Adopted.
