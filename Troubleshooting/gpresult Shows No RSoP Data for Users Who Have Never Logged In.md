gpresult Shows No RSoP Data for Users Who Have Never Logged In

## Symptom

Ran `gpresult /r /scope user /user mujtaba\jordan.lee` (and the same for sam.patel) to verify a Group Policy Object had inherited correctly to their OUs. Both returned an error stating the users had no RSoP data.

## Diagnosis

Confirmed the GPO was correctly linked at the parent OU and that both accounts existed in the expected sub-OUs. The command itself was correct in form — the issue was with what it was actually asking for.

## Root Cause

`gpresult` reads a cached Resultant Set of Policy (RSoP) record generated by an actual past logon event — it doesn't calculate policy live for accounts that have never logged on anywhere. Both accounts had never logged into any machine (including being blocked from logging into the DC itself — see [Domain User Login Denied on Domain Controller](Domain%20User%20Login%20Denied%20on%20Domain%20Controller.md)), so no cache existed for the tool to read.

## Fix

Used the Group Policy Modeling Wizard (Group Policy Management > Group Policy Modeling) instead, which simulates policy application for a target user/OU without requiring a real prior logon. This confirmed the GPO's inheritance correctly for both accounts.

## Takeaway

`gpresult` is a diagnostic tool for confirming what's already applied via a real logon, not a planning/simulation tool. For any account that hasn't logged on yet, use Group Policy Modeling instead.
